# #135 — Communicating our user journey in a way which shows the app's core journey too

`source: edstem thread #135`

**Question:** A group working on a social app for art/craft hobbyists asks whether to present their features in user-journey order (profile creation → discovery → connection) or in the order they were designed (discovery first), and how to weave in their design process without making the narrative confusing.

**Answer (Mark Wheelhouse):** Present in user-journey order — presenting interactions out of sequence will make the narrative confusing (analogous to explaining a compiler's back-end before the front-end). You do not need to cover every design detail; instead, repeat this structure 2–3 times to cover your main stakeholder journeys:

- Introduce a user journey involving your service
- Demo the relevant user interaction(s)
- Discuss how you designed/developed/implemented that interaction (including some iteration, but not every step)

For the final presentation you are showing the finished project, not the exact path taken to build it. Prefer showing the live app over screenshots ("show, don't tell").
