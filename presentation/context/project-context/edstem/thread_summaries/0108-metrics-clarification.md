# #108 — Metrics clarification

`source: edstem thread #108`

**Question:** A student asks whether timing counts as a "meaningful" metric (versus a generic one) when it measures how long stakeholders take to complete specific tasks, and whether the learning/memory effect of repeated testing introduces unavoidable bias that can simply be acknowledged in results.

**Answer (Mark Wheelhouse):** Assessment focuses on *what* is being measured and how well it is analysed — not the form the metric takes (time, clicks, failures). A metric is meaningful if it targets context-relevant tasks specific to your system; generic/non-meaningful metrics are things unrelated to your system's core purpose (e.g. time to login) or heavily influenced by external factors (e.g. ICT response time). On stakeholder bias from repeated exposure: try to maintain a roughly consistent proportion of new vs. experienced users across each iteration in which metrics are gathered (ideally at the same time as user interviews). If that is not achievable, acknowledging the bias when presenting results is acceptable.
