# #115 — Clarification for similar themes

`source: edstem thread #115`

**Question:** A group used their first week's theme to build a basic system for the core interaction, then planned a second week focused on improving "engagement" via new interactions (notifications, collaboration, editor). They asked whether having both weeks' themes centred on the same problem statement would be penalised for being too similar.

**Answer (Mark Wheelhouse):** Several points to address:
- "Getting a basic system for the core interaction" is not a good theme choice — themes must be framed around a clear user need for a specific set of stakeholders, not just feature completeness.
- "Engagement" (if clearly framed in the problem context) is a better high-level theme for the second week.
- Development work must be discussed and presented in terms of user stories/needs, not as a bare feature list — tasks, notifications, collaboration, and editors only make sense when tied to specific user needs within the problem context.
- If the two weeks implement entirely separate interactions, a distinct theme for each should be achievable. Regardless, novelty of the theme is not itself an assessed criterion.
