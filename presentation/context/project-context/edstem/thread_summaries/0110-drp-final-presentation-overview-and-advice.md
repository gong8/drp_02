# #110 — DRP Final Presentation Overview and Advice

`source: edstem thread #110`

**Question:** What are the expectations, structure, and practical advice for the DRP Final Presentation, including timing, required content, and submission requirements?

**Answer (Mark Wheelhouse):** The following covers the key requirements and advice for the DRP Final Presentation:

- **Timing:** 20 minutes to present (strictly timed), followed by 5 minutes of Q&A, plus 5 minutes reserved per slot for AV/logistics setup in rooms 308/311/145.
- **Format:** Presentations should be given live (demonstrations especially); pre-recording the opening pitch (first 3–5 mins) is permitted. Each group member must speak for at least 3–4 minutes, ideally an equal share.
- **Required content (in any order that tells a coherent story):**
  - Introduction and opening pitch/mini-demo (~5 min max): motivating problem, target users, "How Might We" statement, and HCD techniques used.
  - Detailed description of the proposed solution: user journeys (ideally via personas), how users interact with the touchpoint, and how HCD issues are addressed.
  - Application structure and implementation: languages, frameworks, component interactions, a **system architecture diagram**, justification of choices vs. alternatives, and enough detail for a future development team.
  - Demonstration of the digital touchpoint in action, blended into the presentation rather than separated out.
  - Evaluation: outcomes, user impact, future work, lessons learned, and what would be done differently.
- **Practical presentation advice:**
  - First slide must clearly state your group number and project title.
  - Keep the problem description to ~2 minutes before showing the product; do not exceed 5 minutes on it.
  - Avoid slides dense with text or code; use pictures, diagrams, and graphs. Check text/background contrast in the actual room.
  - Do not introduce personas as abstractions ("Meet Bob…" works fine); do not use the word "demo" in isolation on a slide — blend it in.
  - Demo a working (even if older) version; do not attempt to debug or write code live.
  - Aim for just over 19 minutes to leave room for Q&A. Rehearse with other groups.
  - Avoid generic project management content (group structure, collaboration tools).
  - Be prepared for Q&A questions on material not covered; admitting uncertainty is better than guessing.
  - The app should be robust to arbitrary inputs; application crashes or obvious glitches will be penalised. (Volume of data is not a concern — representative data is sufficient.)
- **System architecture diagram:** use a sensible number of components (not 2, not 20), provide a key explaining what arrows represent, and use meaningful component names.
- **Slides submission:** submit ***final_presentation_slides.pdf*** to Scientia by **7pm on Friday 19th June**. This is for assessment records only and does not affect the presentation mark.
- Last year's top 6 presentations are available on Panopto: [Best DRP Final Presentations 2024-2025](https://imperial.cloud.panopto.eu/Panopto/Pages/Sessions/List.aspx?folderID=c48136fc-772c-4b46-869e-b44a008e5134).
