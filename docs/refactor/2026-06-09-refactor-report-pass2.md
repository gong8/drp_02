## 1. Decompose events.create() god-mutation into pure candidate-normalization + deadline-validation helpers in logic/

`decompose-events-create-god-mutation` - **effort** M | **risk** low | **impact** med | **status** applied

### Problem / summary
events.create (apps/api/src/routers/events.ts:481-650) is the file's largest function (~170 lines). It interleaves four separable, fully-pure concerns with the imperative insert: (a) TIME-candidate map/filter/sort/minute-dedupe + past-time throw (489-518), (b) ACTIVITY-candidate trim/empty-drop/case-dedupe (520-539), (c) decidesBy validation+default with its NaN/past/too-late triple-guard (584-599), and (d) replyBy validation whose floor depends on decidesBy (604-616). None of (a)-(d) touch db/ctx/await. The candidate-shaping rules are documented as mirroring addCandidate's startMinute/activityKey dedupe (events.ts:759,777) yet are re-spelled inline. The codebase already establishes logic/ for exactly this kind of pure helper (plan-activity.ts, past-meetups.ts) with co-located unit tests, but create() is reachable only through the full tRPC harness. Extracting these helpers turns create into an orchestration shell and gives the rules a fast pure-unit test seam, while the existing events-create.test.ts (686 lines, covers same-minute collapse at 488, case-insensitive activity dedupe at 590, decidesBy bounds 318-412, replyBy bounds 417-478) verifies behavior is byte-identical.

VERIFIED: line refs, helper definitions (startMinute/activityKey/MINUTE_MS at 112-118; resolveMomentEnd/MOMENT_MS at 143-148; DEFAULT_HORIZON_MS at 53; defaultDecidesByForCandidates imported at 12), addCandidate reuse of startMinute/activityKey (759,761,777,778), the pure logic/ precedent, and full test coverage all confirmed. The asymmetric ID indexing is real and load-bearing: `_t${i+1}` is assigned in the FIRST map (before filter+sort, so index = original input order), `_a${i+1}` in the TRAILING map (after trim/drop/dedupe, so index = post-filter position). Do it in two commits: candidate-normalization first (clean win, M/low), deadline-derivation second (riskier, M/low-med).

### Why it matters
create() is the largest function in the largest API router (events.ts, 1101 lines) and the prior four /simplify-refactor passes deliberately skipped structural work like this. The four concerns are genuinely pure (no db/ctx/await), so extraction is a mechanical move with a strong existing precedent (logic/plan-activity.ts, logic/past-meetups.ts each with co-located pure unit tests). The payoff is real: create() becomes a readable linear orchestration (normalize -> validate locks -> derive anchors -> derive deadlines -> insert), the candidate-shaping rules stop being re-spelled inline next to their addCandidate twins, and the rules gain a fast pure-unit test seam they currently lack (today they are only reachable through the full DB-backed tRPC harness). Behavior, row IDs, ordering, dedupe semantics, deadline guards, and every TRPCError message stay byte-identical, and the existing events-create.test.ts already pins all of them.
