### 1. Export shared RouterOutputs/RouterInputs from lib/trpc.ts instead of per-screen Awaited<ReturnType<...>>

**Effort:** S | **Risk:** low | **Impact:** med | **Reach:** 12 files | **key:** `mobile-router-types-shared-helper`

**Problem.** Ten-plus call sites across six mobile source files (plus four test files) re-derive tRPC procedure rows with the verbose, brittle `Awaited<ReturnType<typeof trpc.X.query>>[number]` idiom. The same procedure gets re-derived independently in multiple places (`groups.mine` in GroupsList + CreateWizard; `events.mine` in Dashboard + notifications). tRPC ships `inferRouterOutputs`/`inferRouterInputs` for exactly this, and the repo forbids hand-writing API types, but the canonical `RouterOutputs`/`RouterInputs` aliases are unowned. Centralize them in lib/trpc.ts and replace the idiom. Pure type change, no runtime impact.

**Why it matters.** Removes a brittle, duplicated type idiom from 6 source files (10+ sites), giving the codebase the one canonical RouterOutputs/RouterInputs aliases tRPC ships for this. Matches the stated "types follow automatically" convention and the no-hand-written-API-types rule. Low effort, low risk (pure type change), broad reach across the mobile client.

**Change steps.**

- CreateWizard.tsx:29-30 - `type Group = RouterOutputs["groups"]["mine"][number];` and `type PastMeetup = RouterOutputs["events"]["pastForGroup"][number];`.
