# #90 — Optimal Fidelity Interleaving

`source: edstem thread #90`

**Question:** When doing paper-based mock-ups, at what point is it best to transition to technical implementation — and what is the optimal interleaving of paper mock-ups and code for developing a solution?

**Answer (Mark Wheelhouse):** There is no single optimal switch point; instead, treat convergence of a specific interaction as the signal to move to code — typically after roughly 2–5 user feedback iterations on that interaction. Key points:
- Work interaction by interaction, not system-wide; mapping out the entire service on paper first is inadvisable, especially given DRP milestone requirements for technical progress.
- Expect that at some point (for most groups, around the week of the post) it becomes faster to iterate directly in the digital touchpoint once the interface is sufficiently refined.
- Even after that point, brand-new interactions are still best started on paper until they reach initial convergence.
